# 浏览器微信登录与小程序账号联合

## 开通与配置

小程序 AppID 与微信开放平台「网站应用」AppID 是两套独立凭据，不能互换。本功能使用网站应用的 `snsapi_login` 授权，小程序继续使用原来的 `wx.login` 与小程序凭据。

1. 在 [微信开放平台](https://open.weixin.qq.com/) 注册或登录开发者账号，按平台要求完成开发者资质认证。
2. 在管理中心创建「网站应用」，提交网站信息及平台要求的申请材料，申请微信登录能力并等待审核。资格、材料和审核要求以当前开放平台控制台为准。
3. 审核通过后，取得**网站应用**的 AppID 与 AppSecret，在网站应用开发配置中登记浏览器访问的授权回调域名。填写域名，不填写 `/oauth/wechat-web` 路径。
4. 将现有小程序关联到**同一个微信开放平台账号**。网站应用与小程序的 OpenID 不同，联合登录仅使用微信服务端返回的 UnionID；昵称、头像、手机号或客户端提交的标识不会被当作联合身份凭据。
5. 在 Go 后端根目录 `.env` 或部署环境中填写：

```dotenv
WECHAT_WEB_APP_ID=网站应用的AppID
WECHAT_WEB_APP_SECRET=网站应用的AppSecret
WECHAT_WEB_REDIRECT_URI=https://浏览器访问的域名/oauth/wechat-web
```

完整回调地址要求 HTTPS，路径固定为 `/oauth/wechat-web`，不接受额外查询参数。不要把网站应用 Secret 填入前端、小程序或聊天消息。`.env.example` 也保留了这三个配置项。配置后重启 Go 后端。

## 登录行为

浏览器登录页在微信页签发起一次性授权流程，并展示微信官方 `qrconnect` 页面。使用官方 SDK 的 `login_type=jssdk`、`self_redirect=false` 参数，保留默认快捷登录能力：是否展示已登录桌面微信的快捷授权由微信官方页面、客户端版本与浏览器支持决定；平台不会自行扫描本机进程，也不保证所有设备都能免扫码。

用户确认授权后，微信回到浏览器 `/oauth/wechat-web` 页面，由后端交换授权码。授权状态绑定发起浏览器的 HttpOnly Cookie，十分钟过期且只能使用一次。微信访问凭证不下发到客户端，也不写入登录日志。

- 唯一有效的小程序绑定且平台账号可用：创建浏览器登录会话，进入平台。
- 微信尚未绑定：提示先在小程序中绑定，再登录；不自动注册账号。
- 缺少 UnionID：按未绑定处理。旧绑定若此前未获得 UnionID，在完成开放平台关联后重新使用小程序微信登录，以更新绑定身份。
- 同一 UnionID 对应多个不同平台账号：拒绝登录，需要先核对账号归属。
- 绑定已解除、账号禁用、状态过期或重复回调：不签发会话。

微信昵称与头像保持现有可选资料流程：用户显式选择头像后，小程序以 Base64 上传，后端规范化为有大小限制的 JPEG 存入数据库，通过鉴权头像接口返回；没有选择头像时使用 WX 占位图。微信登录码兑换接口本身不返回头像，不会根据昵称猜测或抓取头像。

## 验收

开通前可以验证配置缺失、状态校验和本地回归。开通后使用登记域名的 HTTPS 环境分别验收：已绑定用户、未绑定用户、无桌面微信的扫码用户，以及有桌面微信的快捷授权用户。真实授权不能用小程序 AppID 或虚构网站应用配置代替。

参考：[微信网站应用登录开发指南](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)、[微信官方登录 SDK](https://res.wx.qq.com/connect/zh_CN/htmledition/js/wxLogin.js)。
