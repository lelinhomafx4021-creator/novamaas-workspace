# 图片模型对接

管理目标：通过公司平台提供图片生成与编辑能力，星途负责参数交互、结果展示及本地成果保存。平台已有基础能力，星途旧媒体调用仍需适配，完整链路尚未验收。

## 一、范围与现状

图片生成、图片编辑和向文本模型提交图片属于不同能力，分别确定入口、协议及验收范围。星途保留媒体工具和成果保存代码，常规媒体选择器受当前产品配置限制；功能开放须同时完成入口配置与接口适配。

平台负责模型、渠道、权限及计费；星途负责现有工具动作、调用参数、结果解析及项目或会话关联。模型在目录中可见，不等于参考图、尺寸或输出格式已经可用。

## 二、实施流程

1. 确定一个实际图片入口、模型及生成或编辑动作，形成首条可验证链路。
2. 对照所选模型支持的尺寸、数量、参考图及返回形式配置客户端选项。
3. 适配旧媒体请求和结果解析，完成真实生成及错误反馈。
4. 下载并保存实际图片文件，关联原项目或会话，验证重新打开。
5. 完成权限、异常及账务核查后开放对应入口。

## 三、异常与结果管理

| 场景 | 处理要求 |
| --- | --- |
| 提交超时且结果不明 | 优先核查实际结果，避免自动重复付费提交 |
| 等待中停止 | 区分停止本地等待与取消上游生成，按实际支持能力反馈 |
| 结果为远端地址 | 作为文件获取来源，长期成果保存实际文件 |
| 查询或取消 | 按所选协议实现，不能套用一个适用于所有图片模型的通用任务流程 |

## 四、已有接口与字段

| 方法与路径 | 请求方式 | 接入说明 |
| --- | --- | --- |
| POST /v1/images/generations | JSON | OpenAI 兼容图片生成，使用模型 API Key |
| POST /v1/images/edits | JSON 或 multipart/form-data | 图片编辑，传图格式由模型及渠道决定 |
| POST /api/v3/images/generations | 原生 JSON | Volc Native 图片链路，不直接套用 v1 参数 |

| v1 请求字段 | 类型 | 必填 / 规则 |
| --- | --- | --- |
| `model` | string | 必填，实际可调用模型 ID |
| `prompt` | string | 必填，生成描述或编辑指令 |
| `n` | integer | 可选，客户端提交 1–128，具体模型上限可能更低；不自动批量重试 |
| `size` | string | 可选，按模型支持，如 1024x1024；不作为所有模型通用默认 |
| `quality` | string | 可选，枚举按模型能力，不能统一写死 standard / hd |
| `response_format` | string | 可选，url / b64_json，须链路支持 |
| `stream` | boolean | 可选，仅支持流式图片的链路使用 true |
| `image` / `images` | 模型定义的字符串、数组或上传文件 | 编辑或参考图场景条件必填；不将 JSON 和 multipart 两种格式混用 |
| `mask` | 模型定义格式或上传文件 | 局部编辑条件使用，需符合模型尺寸和透明度规则 |
| `watermark` | boolean | 可选，模型支持才传，false 不能被省略成未设置 |
| `seed` | integer | 模型扩展字段，支持范围及零值由实际适配确认 |
| `output_format` / `background` / `input_fidelity` | 模型定义格式 | 只在对应适配通过后开放，不由 /v1/models 自动推断 |

生成请求节选，模型 ID 和尺寸须替换为已验证值：

```json
{"model":"<实际图片模型ID>","prompt":"办公室里的桌面绿植","n":1,"size":"1024x1024"}
```

| v1 非流式成功字段 | 类型 | 接收要求 |
| --- | --- | --- |
| `created` | integer | 通常为 Unix 秒，按实际协议记录 |
| `data` | object[] | 图片结果列表，按实际返回数量保存 |
| `data[].url` | string | URL 结果时提供，及时下载实际文件 |
| `data[].b64_json` | string | Base64 结果时提供，解码后保存文件，不把编码文本当下载地址 |
| `data[].revised_prompt` | string | 可选，模型提供的改写说明 |
| `usage` / `metadata` | object | 链路提供时解析，不能假定全部模型存在同形用量 |

URL 与 Base64 按实际响应处理，不要求两项同时存在；缺少可用图片内容时不报告生成成功。流式图片使用对应模型的事件适配，不能用文本 delta 解析图片。原生 v3 的参考图、尺寸和响应字段按选定模型单独映射；平台保留原生协议不等于星途已适配。

平台当前没有覆盖所有图片模型的通用异步查询、取消接口。/v1/models 仅发现模型，不能据此得出完整参数规格、功能能力和准确报价。错误按模型协议对象读取，避免将超时结果不明重试成多笔生成。

## 五、验收标准

验收包括实际入口可达、图片生成、拟开放的参考图或编辑、失败响应、文件保存、重新打开和实际密钥账户的调用用量。平台单独调用与星途完整链路分别记录；完整通过后标记已验收。

图片作为视频参考素材时，另按[视频模型对接](/admin-manual?article=video-models)核对素材上传和引用条件。
