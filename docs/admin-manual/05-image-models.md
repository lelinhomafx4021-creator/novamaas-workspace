# 图片模型对接

管理目标：通过公司平台提供图片生成与编辑能力，星途负责参数交互、结果展示及本地成果保存。平台已有基础能力，星途旧媒体调用仍需适配，完整链路尚未验收。

## 一、范围与现状

图片生成、图片编辑和向文本模型提交图片属于不同能力，分别确定入口、协议及验收范围。星途保留媒体工具和成果保存代码，常规媒体选择器受当前产品配置限制；功能开放须同时完成入口配置与接口适配。

平台负责模型、渠道、权限及计费；星途负责现有工具动作、调用参数、结果解析及项目或会话关联。模型在目录中可见，不等于参考图、尺寸或输出格式已经可用。

## 二、实施流程

1. 确定一个实际图片入口、模型及生成或编辑动作，形成首条可验证链路。
2. 对照所选模型支持的尺寸、数量、参考图及返回形式配置客户端选项。
3. 适配旧媒体请求和结果解析，完成真实生成及错误反馈。
4. 下载并保存实际图片文件，关联原项目或会话，验证重新打开。
5. 完成权限、异常及账务核查后开放对应入口。

## 三、异常与结果管理

| 场景 | 处理要求 |
| --- | --- |
| 提交超时且结果不明 | 优先核查实际结果，避免自动重复付费提交 |
| 等待中停止 | 区分停止本地等待与取消上游生成，按实际支持能力反馈 |
| 结果为远端地址 | 作为文件获取来源，长期成果保存实际文件 |
| 查询或取消 | 按所选协议实现，不能套用一个适用于所有图片模型的通用任务流程 |

## 四、验收标准

验收包括实际入口可达、图片生成、拟开放的参考图或编辑、失败响应、文件保存、重新打开和实际密钥账户的调用用量。平台单独调用与星途完整链路分别记录；完整通过后标记已验收。

图片作为视频参考素材时，另按[视频模型对接](/admin-manual?article=video-models)核对素材上传和引用条件。
