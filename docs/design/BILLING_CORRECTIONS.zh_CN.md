# 历史消费有效金额与模型计费调账

实施日期：2026-10-09。本文记录本轮调账实现、资金边界及验收方法；与 [账单导出说明](BILLING_STATEMENT_EXPORTS.zh_CN.md)、[历史核验说明](BILLING_HISTORY_REVIEW.zh_CN.md) 配套使用。

## 1. 原始记录、有效金额与审计日志

调账保留原始消费/退款日志、任务计费快照、历史导入凭证、原始账务分录和上游成本快照。执行时新增关联到原始分录的修正分录，读取时计算：

```text
当前有效金额 = 原始金额 + 所有已执行修正分录 + 所有已执行撤销分录
本次差额     = 新规则重算金额 - 当前有效金额
```

用户的消费日志、按令牌查询的日志、日/月消费明细和小时汇总显示有效金额及有效计费组；管理员查看同一消费行也采用有效金额。原日志数据库中的原始金额不会被覆盖，不能因修改展示口径丢失资金凭证。普通用户不会看到独立的调账审计记录。

原有类型 8「费率调账」日志继续保留，用于记录执行/撤销时间、操作者、批次和差额；不删除已有日志。普通消费、收入和利润汇总排除独立类型 8，再把差额归入原消费/退款记录，避免同一差额计算两次。管理员明确筛选类型 8 时仍可按实际执行日期查询审计差额。

原始上游请求次数、token 用量和实际供应商渠道 ID 不变。首页原有 `quota_data` 图表是消费总额口径，只修正原消费行，不新增退款行；退款和净额在消费统计、日/月账目及正式对账单中体现。按客户计费组过滤的成本归属随有效消费行移动，以对齐该组的收入和利润；原成本金额、永久成本快照及实际供应商渠道归属保持不变。

## 2. 历史对账单作废与重建

系统已有「作废对账单 → 创建新版本」流程，本轮复用该流程，并补上已确认账单存在后续调账时的提示。无需作废历史导入凭证。

1. 调账执行后，受影响的草稿、已下发或已确认账单提示存在未纳入的修正。
2. 管理员填写原因，作废受影响账单。
3. 为同一月份创建新版本，新版本按原消费/退款发生月份纳入最新修正，而不是把历史消费差额移到调账执行月份。
4. 重新归档、下发并由客户确认。

旧 PDF、Excel、明细、指纹、确认时间和确认回执仍保留。新版本冻结创建时的账务序号，后续调账或撤销不会修改已归档版本；需要再次作废并重建才能纳入后续变化。作废、重建和下载文件均不会再次扣除余额。

若旧版本曾按调账执行月份纳入差额，系统要求先作废该月份的旧版本，防止两个有效月份重复纳入同一笔差额。

## 3. 渠道变化调账与余额

界面名称为「渠道变化调账」，接口模式为 `group_rate`，旧客户端省略模式时继续使用该模式。

这里的渠道是客户计费组及其折扣比例。选择时间、模型和目标计费渠道后，沿用历史模型计费参数，变更组折扣；不会改变已经发生的实际上游供应商请求。若此前已经做过模型计费调账，则继承上次冻结的有效模型价格，避免恢复为旧价格。

执行按照批次净差额处理钱包：

| 净差额 | 钱包动作 |
| --- | --- |
| 大于 0 | 追加扣除余额 |
| 小于 0 | 退回余额 |
| 等于 0，但扣费/退款行存在差异 | 修正账目，余额不变 |
| 所有行均无金额差异 | 无需调账，禁止执行 |

完全退款的任务仍可能同时修正扣费和退款两侧，不能仅因净差额为零而禁止修正。余额不足、令牌额度不足或计数越界时整笔事务回滚，不会留下部分账目、部分扣款或已占用批次。

钱包、用户消费累计、令牌剩余额度/消费累计、渠道消费累计和修正分录在同一主库事务内更新。重复确认同一已执行批次不会再次扣款；撤销追加反向分录并恢复对应资金和计数。对同一来源连续调账时必须先撤销后执行的批次，再撤销前一批次。

## 4. 模型计费变化调账

新增模式 `model_pricing`，界面选择时间和模型，无需选择目标计费渠道。重算使用当前模型价格以及每笔记录已有的有效计费组/折扣；此前已确认的渠道变化不会被覆盖。

- 区分任务提交扣费、最终差额结算及失败退款，按累计状态重算各来源分录，不直接按金额比例缩放已取整结果。
- 当前按次价格和 token 价格变化均可重算；当前计费方式决定是否进行 token 最终结算，不沿用旧「按次计费」标记。
- Seedance 使用已保存请求中的输出分辨率和输入视频条件，以及成功任务响应中的 `usage.total_tokens`。
- 优先读取独立请求归档中的实际 upstream 请求，其次原客户端请求，兼容旧任务内嵌请求。通用视频协议读取 `metadata` 中的选项，火山原生协议读取顶层选项。
- 不把旧记录缺少 `video_input` 倍率当成「没有输入视频」，也不猜测缺失的分辨率。
- 失败且完全退款的任务无需成功响应 token 用量，仍可安全重算扣退两侧。

预览保存原始金额、当前有效金额、目标金额、行差额、有效组、目标组、价格参数、分辨率、输入视频条件、前一批次关联及证据指纹。下载预览 JSON 不包含请求提示词、视频 URL、API 密钥或完整请求体。

预览有效期为 15 分钟。确认时重新核对来源分录、任务状态、用量、计费配置和账务序号；任何相关变化都要求重新预览。只有超级管理员通过已登录会话与二次安全验证，并确认目标用户 ID 和净差额后才能执行。财务核算人员可查看页面和记录；跨账户操作仍要求管理员角色及财务核算权限。

### 可处理范围

当前调账范围为有完整任务及账务证据的已完成钱包异步任务，支持按次和 token 计费。订阅、未终结任务、表达式计费、普通聊天日志或缺少完整生命周期证据的记录会阻止整个批次，不会猜价后扣款。每批最多 20 个模型、93 天、1,000 条来源分录；应把同一任务的提交、结算和退款纳入同一时间范围。

## 5. Seedance 2.5 分档价格

以下参考价格来自本次产品需求附件，单位为人民币/百万 token。分辨率及输入视频条件的倍率规则同时用于新请求和历史重算。

| 模型系列 | 分辨率 | 无视频输入 | 有视频输入 |
| --- | --- | ---: | ---: |
| Seedance 2.5 | 480p / 720p | 70 | 42 |
| Seedance 2.5 | 1080p | 77 | 46 |
| Seedance 2.0 | 480p / 720p | 46 | 28 |
| Seedance 2.0 | 1080p | 51 | 31 |
| Seedance 2.0 | 4k | 26 | 16 |

本轮为以下两个精确模型名接入 2.5 分档：

```text
doubao-seedance-2-5
doubao-seedance-2-5-260628
```

2.5 相对于无视频输入 720p 基准的倍率分别为 `1`、`42/70`、`77/70`、`46/70`。480p 与 720p 使用相同价格。2.0 的现有价格和 4k 规则继续保留；2.5 的 4k、未知或非字符串分辨率在新请求验证时返回 400，历史重算也拒绝未知组合。

平台的 `ModelRatio` 是可配置基准价，分档规则按该基准乘倍率。任何显式自定义价格都保留；如果配置了固定 `ModelPrice`，按平台现有优先级执行固定价。只有日期别名未配置时，才继承 `doubao-seedance-2-5` 已配置的基准倍率；若两者都未配置，采用代码默认值。公开价格列表与实际生效倍率保持一致。

例如汇率 7、基准 `ModelRatio=5` 时，基准为 `5 × 2 × 7 = 70` 元/百万 token。10,000 token、折扣 0.66、1080p 无视频输入的最终金额为 `77 × 10000 / 1000000 × 0.66 = 0.5082` 元；同用量的 720p 为 0.462 元，追加差额为 0.0462 元。实际执行以预览中冻结的整数 quota 为准，并处理提交/结算的取整边界。

## 6. 验收顺序与验证记录

建议操作：选择客户 →「模型计费变化调账」→选择覆盖完整任务生命周期的日期及两个模型名 → 预览 →检查原始/有效/目标金额及扣退差额 →下载 JSON 留存 →安全验证后执行 →刷新原消费日志和日/月统计 →按提示作废受影响月份对账单并创建新版本。

部署本功能不会自动执行历史调账。本轮开发中的资金变更验证均使用隔离测试数据库；真实客户调账由运营人员在预览核实后执行。

回归覆盖：

- 基准价格、完整分辨率/输入视频矩阵、两别名及显式价格优先级。
- Doubao 通用和火山原生请求验证；真实原始/upstream 归档、缺证据阻止及私有信息不泄露。
- 模型提价/降价、按次与 token 计费切换、预扣/结算/退款生命周期、余额不足回滚、重复确认、连续批次和撤销。
- 用户/管理员/令牌日志、有效计费组过滤与分页、缓存即时失效、消费与净额统计、成本金额保留、独立审计防重复计算。
- 主库与日志库分离、ClickHouse 请求标识与跨用户隔离。
- 历史月份作废重建、旧确认凭证保留、新版本冻结、生成文件不重复扣款。
- 前端模式切换与旧预览失效、净差额零的账目修正、有效金额零的显示、已确认账单修正提示及作废入口。
