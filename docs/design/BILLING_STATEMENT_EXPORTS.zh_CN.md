# 月度对账单 PDF / Excel 与重新生成

2026-10-08，NovaMaaS 下游账单导出扩展。平台仍保留 new-api 项目及 QuantumNous 归属。

## 数据边界

正式对账单取不可变 `BillingEntry`，以原账单的用户、时间范围、序号范围汇总，并与冻结的逐日、模型和月度金额相互核对。临时预扣、充值和其他资金变动不作为消费；退款单独列示。金额按原始整数额度转换，保留六位小数。

附件示例包含「总览」「每日汇总」「模型汇总」。新 Excel 沿用这三个工作表的组织方式，仅列示平台能够核验的正式账本字段；缺失值不伪装成零。

| 附件字段 | 正式账单支持情况 | 新导出处理 |
| --- | --- | --- |
| 用户、企业抬头、税号、账期 | 已有冻结信息 | 总览与 PDF 列示 |
| 日期、模型名称 | 正式明细已记录 | 每日汇总、模型汇总 |
| 使用天数 | 可从模型入账日期去重 | 标为「使用账单天数」，退款日期也计入，不等同于调用天数 |
| 成功请求 | 正式明细可能包括多次结算、退款与历史补录，不等同于请求数 | 替换为消费笔数、退款笔数、正式账本记录数 |
| 实际账单 | 可核验 | 明确拆分消费金额、退款金额、本期净额 |
| 模型数 | 可核验月度模型集合 | 总览列示本期模型数量；不添加未冻结的每日模型数量 |
| 实际账单占比 | 可核验 | 模型消费金额占本期消费总额；零消费合计为 0% |
| 输入、输出、缓存写入、缓存读取、总令牌 | 部分消费日志保存相关数据，但正式账本未完整冻结，日志还可关闭或清理 | 不进入正式导出 |
| 标准原价、优惠金额、有效折扣、标准原价占比、平均折扣 | 正式账本没有完整历史原价快照 | 原价列标为「未记录」，不计算优惠与历史折扣 |
| 分组倍率分布 | 正式账本没有保存完整历史分组/倍率 | 替换为生成时当前用户可用的模型计费组费率，标为「当前参考」 |

部分消费日志的 `other` 保存 `model_ratio`、`model_price`、`group_ratio`、`user_group_ratio` 和缓存指标，说明平台存在相关定价线索，但不是覆盖全部计费方式的「历史标准原价」。正式明细未保存这些值，也没有可靠的一对一日志关联，表达式计费、任务分阶段结算及退款尤其不能统一使用「实际金额 ÷ 当前倍率」计算原价。需要准确历史原价时，应另行设计结算时冻结标准价、实际价和费率的明细契约；不回填或推断旧数据。

## 当前参考费率

从当前启用的模型/分组能力中，只保留客户目前有权使用的组，应用用户分组对目标组的专属倍率，转换为百分比。单一费率列示如 `80.00%`；多个不同费率在 PDF 列示范围，Excel 同时列示各组的名称及百分比；无可用配置标为「未配置」。合法的零倍率显示 `0.00%`。费率和采集时间随生成版本冻结，重试不再读取当前配置。它们不会改变正式账本金额，也不证明历史订单实际使用的组。

## 品牌与文件名

对账 PDF 有独立的多页模板，使用与其他 PDF 一致的品牌配置和运营标识安全读取/归一化逻辑。旧模板 7/8 的页眉漏掉了运营标识分支，新模板 9 修复右上角运营标识，并保留旧模板用于已有归档的原样重试。

PDF 和 Excel 的下载名优先使用冻结的企业抬头，未填写时使用冻结用户名，再回退到用户编号：`企业抬头_YYYY-MM_月度对账单_VNN.pdf` / `.xlsx`。保留版本号以区分重新生成版本；路径分隔符与控制字符会清理。确认回执同样优先使用企业抬头。

## 双文件归档与校验

1. 核对原范围的正式账本、逐日汇总、模型汇总和月度合计。
2. 按冻结快照生成 Excel，永久存入同一 OSS 归档资料源，读取校验后获得 SHA-256。
3. 在 PDF 封面写入 Excel SHA-256 和账单快照 SHA-256，再归档 PDF。
4. 校验清单版本 2 同时保存 PDF、Excel、账单快照以及明细分块摘要。客户确认清单摘要，即绑定两个文件；确认事件和回执也列示 Excel 摘要。

Excel 中记录账单编号、版本和快照摘要；不反向写入 PDF 摘要，以避免两个文件相互引用造成循环摘要。金额超过 Excel 15 位有效数字时以原始六位小数字符串保存，避免精度损失；模型名等外部文本不作为公式执行。工作簿 ZIP 顺序和文档时间固定，归档重试生成相同字节。

新模板必须成功归档 PDF、Excel 与校验清单后才能成为可下发草稿。旧模板的归档和确认保持原有规则，不强制补写 Excel。下载继续执行账号权限及 OSS 摘要校验，不提供公开文件链接。小程序使用原鉴权下载接口，并在打开 PDF/Excel 时明确文档类型。

## 重新生成

管理员可对当前草稿、已下发、争议中或已确认的账单选择「重新生成」。该操作使用原时间与序号范围、币种、企业抬头、税号和金额，仅更新呈现模板、当前品牌与参考费率；原范围之后的新消费不进入新版本。

事务建立下一版本并关联来源版本，转移当前有效版本标识。旧文件、原快照、旧状态及确认事件保留，旧版本禁止继续下发、确认、争议、作废或重复重新生成。新版本从准备中开始，成功后为草稿，需要重新下发和客户确认；不继承旧确认。失败时可重试该新版本，旧文件仍可下载。准备中、失败、已作废或已被替代的版本不显示「重新生成」。

不会覆盖 OSS 的既有不可变对象。界面显示并跳转到新版本，满足更新 PDF/Excel 展示文件的目的，同时保留可复核的历史证据。
