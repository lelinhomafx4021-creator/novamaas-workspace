# PDF 文档品牌规范

## 当前范围

| 产出物 | 生成方式 | 品牌来源 | 固定时点 |
| --- | --- | --- | --- |
| 财务对账单与确认记录 | Go 服务端生成、私有存档 | `SystemName`、`Logo`、`OperatingEntityName`、`OperatingEntityLogo` | 创建候选正文时写入版本化快照，Logo 图片也转为有大小上限的 PNG 保存 |
| 供应商测试报告（普通与视频） | 浏览器打印为 PDF | `/api/status` 中的平台与运营主体配置 | 用户导出时读取当前配置，等待图片与字体加载后调用浏览器打印 |

`SystemName` 和 `Logo` 继续表示服务平台；`OperatingEntityName` 和 `OperatingEntityLogo` 单独表示运营主体。两套标识不可互相覆盖。运营主体名称与 Logo 均可留空；配置 Logo 后，两类 PDF 的页眉只显示运营主体标识，不再重复显示名称或“运营主体”标签；只有名称而没有 Logo 时，页眉以名称作为文字标识。测试报告页脚仍可显示运营主体名称。

## 配置与资源

管理员在「系统设置 → 网站设置 → 系统信息」填写运营主体名称和 Logo 的 HTTP(S) 图片地址。地址应稳定、公开可读，并能从后端服务器访问；推荐使用平台长期维护的静态资源地址。财务服务会使用既有的 SSRF 防护下载并压缩图片，再写入对账单快照。浏览器侧报告导出前通过已登录的 API 请求，从同源 `/api/pdf-branding/operating-logo` 取得同样裁切和压缩后的图片，并把图片嵌入打印文档；图片加载失败时给出导出失败提示，避免生成缺失标识的报告。当前配置保存的是图片地址，不提供上传或二进制文件存储；正式使用前仍需配置真实的运营主体 Logo 地址。

## 版式与历史文件

两类 PDF 使用 A4、左右 40 pt 的正文边距。页头左右两组内容都从页面顶端约 42 pt 开始：平台 Logo 使用 38 × 38 pt，右侧裁切后的运营主体 Logo 放入最大 125 × 40 pt 的区域。两组标识垂直居中对齐，页头不再出现多余的运营主体标签。分隔线距页面顶端 100 pt；正文从 119 pt 开始。主标题 26 pt，正文约 8–9 pt，三张摘要卡各高 79 pt，章节栏使用深蓝色，页脚分隔线距页面顶端 784 pt。普通与视频测试报告沿用对账单的字号、色彩、留白和左右对齐方式，表头在每页重复，页脚显示文档名称及页码。测试报告由用户浏览器打印；打印对话框中的纸张和缩放设置仍可能改变最终排版。

当前按实际检查项目生成的普通报告为两页，视频报告为一页，已完成逐页预览核对。人为重复检查项目形成三页以上的极长报告时，Chromium 打印的第三页表头可能缺失；这类输入需要进一步的分页处理，不能将本次预览视为极长报告的验收结果。

新财务单据使用 PDF 模板版本 6，固定运营主体名称与裁切后的 Logo 像素。版本 4、5 的页头继续按原样渲染，已经存档的 PDF 原件保持原字节与哈希；旧快照继续按原模板版本生成确认记录，不读取当前品牌配置。测试报告没有服务端存档，重复导出时使用当时的系统配置。

新增 PDF 功能应先明确平台标识、运营主体标识、A4 页边距、图片加载失败行为，以及是否需要存档与版本快照；涉及有审计或法律效力的文件，应采用财务对账单的固定快照方式。
