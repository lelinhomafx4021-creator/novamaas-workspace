# 节点资源与分类流量监控

系统信息页提供当前节点的硬件状态、网络收发趋势和分类请求统计。监控数据仅存在当前进程的有界内存中，重启后清空。指标采集与查询不访问业务数据库或日志数据库，不读写监控文件，也不依赖 Redis、Prometheus 或新增服务。接口权限沿用现有 Root 登录校验；该校验仍可能读取既有用户或会话数据，不为降低采集开销绕过权限验证。

## 页面与指标口径

入口为 **系统信息 → 资源监控**，原实例信息与后台任务保留为同页独立页签。

| 层次 | 展示内容 | 统计口径 |
| --- | --- | --- |
| 系统资源 | CPU 核数、进程 CPU、RSS、OS CPU 与内存、网卡收发字节和包速率、网络错误与丢包 | OS 对当前进程可见的数据；容器中不承诺物理宿主机全量数据或 cgroup 限额 |
| 入站 HTTP | 模型转发、视频、素材库、存储、管理和其他请求的数量、错误、收发字节、活跃数、重定向数 | 实际消费的请求正文和实际写出的响应正文；不读取或保留正文内容 |
| 出站 HTTP | 转发上游、视频下载、素材库、OSS、Webhook 等请求 | 已接入公共 HTTP Transport 的正文读写；按 RoundTrip 操作计数，内部重放按实际读取的正文累加字节，保持流式处理 |
| 数据库 | GORM 操作、错误、MySQL TCP/PostgreSQL 连接字节与连接数 | 包括协议开销；SQLite 无网络字节；MySQL Unix socket 为保留驱动认证语义，仅记录操作；共享数据库和日志数据库都可被观测 |
| 缓存 | Redis 命令或 pipeline、错误、连接字节和连接数 | 包括 Redis 协议开销；pipeline 计为一次操作，进程内缓存无网络字节 |
| HTTP 连接 | 入站与已接入出站 Transport 的打开连接 | 包括连接池空闲连接；HTTP/2 多路请求共享一个连接，不能与活跃请求数互换 |

活跃请求与连接数同时记录历史：每 5 秒读取一次，分钟聚合与长窗口降采样保留采样峰值。活跃请求历史只统计入站 HTTP，避免将同一业务的入站与出站操作相加。该峰值是采样观测值，不承诺捕捉短于采样周期的瞬时峰值。

网络包数来自网卡采样，应用分类按正文或连接字节统计，不能把两种口径相加，也不能由 HTTP 正文字节精确反推数据包数、TLS 字节或云厂商账单。默认汇总非回环接口；物理网卡、网桥、容器虚拟接口和 VPN 可能观察同一批包，应通过网卡白名单选择需要维护的链路。

视频 `/content` 返回 302 时只记录跳转响应，不把用户之后从上游直下载的视频计入平台流量。代理视频、SSE 等流在读写时即时累加字节，不必等待请求完成；计数器在 EOF、关闭或错误时结束请求。HTTP 错误为 4xx/5xx 与传输错误，不将普通 302 记为失败。

现有中央 Relay HTTP 客户端、SSRF 客户端、素材库客户端、OSS SDK 及 Webhook 接入出站统计。自行创建客户端的其他 SDK 和脱离 HTTP 的 WebSocket 帧不保证完整分类；这些数据仍可反映在网卡总量中。ClickHouse 目前只有 GORM 操作统计，没有专用连接字节统计。

## 低开销采集与内存窗口

请求路径只增加固定类别的原子计数和轻量流包装，不复制请求或响应正文，不记录用户 ID、任务 ID、URL、IP、SQL 或密钥，不因新增请求创建新时间序列。类别固定为模型转发、视频、素材、对象存储、Webhook、管理与其他。

每个 HTTP 操作或被观测连接只在开始时选择一次固定的字节计数分片，后续读写直接更新该分片，减少同类别流请求对同一个计数器的争用。每格固定 16 个分片，28 格共占用 68,320 字节（约 66.72 KiB），不随请求量增长；每个句柄为 16 字节。查询和采样饱和汇总各分片；字节仍在每次读写后即时可见，不延迟到攒满缓冲区或请求结束。出站观测只浅拷贝需要替换正文句柄的请求结构，不再深拷贝 Header、URL 等元数据，仍不改写调用方的 Body/GetBody。

资源每 5 秒采样；CPU 使用独立累计时间差计算，不重复运行旧 CPU 采样器。原性能保护阈值复用同一份 CPU 与内存结果，磁盘保护仍检查既有缓存目录。没有逐次请求写盘、数据库 INSERT 或进程连接表扫描。

历史按分钟聚合，存入当前进程专属的固定容量内存循环数组。启动时按窗口预分配背板，默认 24 小时、1440 个分钟槽位，可配置 1–168 小时，最长 10080 个槽位；满后覆盖最早记录，历史容量不随请求数增长。内存用于分钟资源摘要和固定类别计数，不保留每个请求的明细或正文。当前未结束分钟单独聚合，查询时一并返回。

本地 64 位构建中，每个分钟记录为 1824 字节，默认背板约 2.51 MiB，配置到 7 天时约 17.54 MiB；这些数值只包含历史数组，不包含接口响应、系统采样临时对象或业务内存。关闭监控时不预分配历史背板。

采样、历史更新和查询之间仅有短期内存锁，不在锁内执行文件写入、刷盘、文件迁移或远程上传。纯内存方案不需要写盘队列、重试队列或单独的存储线程。正常关闭时完成最后部分分钟的内存聚合，但不保存到进程外；新进程启动后从本次运行重新采集，旧历史无法恢复。旧版本生成的历史文件不再读取、修改或清理，旧的 `RUNTIME_MONITOR_DIR` 配置不再生效。

查询仅扫描有界内存历史，返回不超过 360 个图表点。页面仅在资源页签激活且浏览器可见时每 15 秒刷新，离开页签或隐藏页面暂停轮询。监控 API 自身不记入 HTTP 分类流量，仍会自然出现在 OS 网卡采样中；既有鉴权产生的 SQL/Redis 操作正常计入对应统计。

页面明确提示“历史仅保存在内存中，重启后清空”，不把主动选择的内存模式显示为磁盘故障。启动初期历史不足两个点时展示采集中状态；可选择的时间范围不超过配置的窗口上限。不可用的 CPU、内存或网卡数据展示为不可用或图表缺口，不填造零值。重启与网卡计数器重置不会产生虚构的流量尖峰。

## 部署与使用

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `RUNTIME_MONITOR_ENABLED` | `true` | 启动时关闭监控采样及 HTTP、SQL、Redis 采集钩子，仅保留原有性能保护采样 |
| `RUNTIME_MONITOR_RETENTION_HOURS` | `24` | 内存历史窗口小时数，范围 1–168；无效值回退至 24 |
| `RUNTIME_MONITOR_INTERFACES` | 全部非回环接口 | 逗号分隔的网卡白名单，例如 `eth0,eth1`；用于避免虚拟接口重复统计 |

接口为 `GET /api/system-info/monitor?minutes=60`，参数允许 1–10080 分钟，实际范围受内存窗口上限约束。`meta.storage` 返回 `mode: "memory"` 与 `capacity_points`，表示存储模式及分钟槽位容量。普通用户与非 Root 管理员不能读取硬件和监控数据，响应禁止共享缓存。

开关在客户端与数据库初始化之前读取，修改后需要重启，不提供运行时热切换。关闭时不安装入站包装或 GORM/Redis 钩子，出站客户端、SQL/Redis 连接使用原生实现，不预分配历史数组。已安装包装的防御性旁路不等同于重建客户端；例如 `http.Client.Timeout` 对自定义 Transport 的取消兼容成本只有在启动时直接使用原生 Transport 才能完全避开。启用监控时保留既有总超时、取消、重定向与连接池语义。

本期只提供当前单节点、当前进程的运维视图，节点名与最近采样时间始终显示。扩缩容、重启、升级或进程异常退出均会清空内存历史；该数据用于实时维护，不作为账单、永久审计或故障后的持久追溯依据。无需为监控数据配置磁盘目录、持久卷或中间件。

## 验证边界

自动回归覆盖计数与流式字节、错误与重定向、连接生命周期、SQLite 操作、Redis 流量、SQL 方言配置、内存容量和过期覆盖、启动会话清空、跨窗口流请求、资源不可用与网卡计数器重置、Root 权限、时间范围校验，以及页面切换、轮询暂停、错误重试和多语言键完整性。

前后端实际运行与截图使用独立的本地 SQLite，不连接公司数据库、不启动 Docker。MySQL/PostgreSQL 的真实专线部署仍需在对应测试库核验 TLS、代理和网卡选择；本地通过不等价于完成生产实库验收。

视频验收使用 1 MiB 本地数据：代理模式应增加入站发送与出站接收各 1 MiB；302 模式仅记录跳转正文，客户端直下不增加平台视频正文流量。纯内存验收额外检查旧监控目录的文件与内容保持不变、新进程不恢复旧流量、内存中仍正常产生运行期间趋势，以及桌面和手机页面的存储提示与布局。

纯内存版本已完成完整 Go 与 relaykit 回归、runtimewatch 竞态检测、前端 121 个文件共 655 项测试、类型和功能目录检查，以及前后端原生构建。真实进程重启前先生成视频流量，重启后该类统计为空并重新采集；旧监控目录两个文件的大小、修改时间和 SHA-256 全部不变。再次执行视频下载后分类统计正常。桌面和手机页面均无横向溢出或浏览器运行错误，显示内存模式说明，默认不提供超出 24 小时的查询按钮。

本地 macOS 无 CGO 构建无法读取主机 CPU 时，页面保留未采集标记；进程 CPU、RSS、主机内存与网络数据正常显示。监控内存窗口的容量不等于整个程序的 RSS；接口响应、运行时及业务本身也会占用内存。

## 请求路径优化验证（2026-10-16）

采用相同的 Gin、正文与 HTTP 夹具比较优化前后，Go 1.26.1、macOS arm64、Apple M1 Max，每项重复 5 次、每次 300 ms，取中位数。入站与出站基准串行执行；本机不保证 CPU 独占。下表为启用监控时的完整夹具操作耗时和分配，不能直接当作接口端到端延迟或生产 P95/P99。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 出站 1 KiB JSON，内存 Transport、单线程 | 0.918 µs，1332 B / 12 次分配 | 0.446 µs，692 B / 8 次分配 |
| 入站 1 MiB 视频、32 KiB 写块，8 并发吞吐摊销 | 11.106 µs/op | 0.558 µs/op |
| 入站 4 KiB SSE、64 B 写块并 Flush，8 并发吞吐摊销 | 22.824 µs/op | 0.492 µs/op |
| 出站真实 HTTP/1 回环 1 KiB JSON，无总超时、单线程 | 38.395 µs，10371 B / 117 次分配 | 36.823 µs，9730 B / 113 次分配 |
| 出站真实 HTTP/1 回环 1 KiB JSON，30 秒总超时、单线程 | 40.708 µs，12083 B / 139 次分配 | 39.662 µs，11443 B / 135 次分配 |

内存 Transport 和入站响应丢弃夹具用于放大包装、计数与竞争成本，不包含真实网络等待，不能据此声称业务视频下载或 SSE 延迟提升相同比例。真实回环夹具复用相同连接池与正文，仍不包含 TLS 或公网链路。1 MiB 出站内存夹具单线程约 19.2 µs，前后差异属于测量噪声，不宣称收益。

普通入站 JSON 的开销没有消失：优化后原生 Gin 夹具约 5.779 µs，监控约 6.103 µs，差值约 0.324 µs、136 B / 4 次分配。真实出站回环 HTTP 也仍有约 5–7 µs 的额外成本；正文包装和 Go 对自定义 Transport 的兼容路径继续存在。短请求并非所有场景都变快，主要收益在出站元数据分配与流式并发计数；不通过改变超时、取消或实时字节口径来换取基准数字。

优化后的完整 Go 与 relaykit 功能回归、监控相关包竞态检查、静态检查和原生后端构建均已通过。扩大检查时另外发现既有日志计数竞态，在干净基线提交复现后改用原子计数与轮换调度；视频轮询测试提前捕获不变任务 ID，避免与 GORM 更新并发访问同一对象。修复后 service 全套竞态检查通过。

启动时关闭监控的夹具确认出站构造返回原 Transport，分配与原生路径同为 192 B / 2 次；真实启动流程直接省略入站中间件。对已安装中间件的防御性旁路也没有额外分配，本机空处理夹具仅多约 3 ns 分支成本。独立 SQLite 进程分别以开启与关闭配置验收 1 MiB 视频代理、302 跳转和直下：开启时入站发送与出站接收各准确增加 1 MiB，跳转仅 63 字节且不请求上游；直下不增加平台正文流量。关闭时业务响应保持一致，所有监控请求数与字节均为零、采集器未启动、历史为空。再次启用后从新会话开始，旧监控文件的大小、修改时间和 SHA-256 不变。

优化版本再次完成桌面与手机页面验收，分类流量、数据库页签、时间范围切换和可见页面轮询正常，无页面运行错误或横向溢出；验收截图包含桌面总览、数据库分类、手机总览与手机出站流量。
