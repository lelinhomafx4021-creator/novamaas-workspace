## 1. 目标与范围

由 Gateway 统一管理星途用户的功能权限。同一个星途安装包，登录不同账号后，根据默认规则、订阅套餐和用户单独设置，显示不同功能。

管理员在 Gateway 后台配置，星途联网读取并落实；同时控制“能否看到”和“能否使用”。需要达到三个结果：

- 可以对所有用户统一开放或关闭某项功能。
- 可以给不同套餐开放不同功能，并对单个用户做例外设置。
- 后台调整后，已支持权限机制的星途版本可以更新现有功能的开放范围，无需重新安装。
- 插件名称、图标、排序、详情由 Gateway 管理，星途读取本人可见目录。
- 插件版本发布、统一版本、强制更新、暂停、撤销和回滚均由 Gateway 决策，星途负责核验、安装和报告；不继续独立获取 latest。

对接范围包含文本、图片、Wan 视频、Seedance 视频、云端素材库、插件管理页、已登记业务插件及其发布控制。技能、MCP 的逐项授权以后可复用机制，不在本次重构其运行系统。Gateway 是管理与规则中心，星途只接入和执行，不另建可独立授予权益的运营后台。按用户最新决定，每插件统一指定版本及期限，全部获授权用户执行同一要求。

### 已有能力和缺口

| 已有能力，已读代码核对 | 需要补齐 |
| --- | --- |
| 星途已接 Gateway 登录、续期、钱包和订阅读取 | 在同一登录身份下读取最终功能权限 |
| 本机企业配置能隐藏插件设置导航；插件已有管理 IPC 和运行配置 | Gateway 按用户远程下发规则，星途在显示、管理操作和业务插件执行时检查 |
| 星途保留旧企业“团队管理后台”网页入口，但后台地址为空，旧账号功能关闭 | 在 Gateway 现有管理后台新增入口；旧企业角色不作为 Gateway 管理身份 |
| Gateway 已有套餐、订阅、模型访问和用户 Key | 增加功能授权关联、统一权限计算及可信的星途专用 Key 绑定 |
| 星途已有 npm/clawhub/git/local 安装和本地更新 IPC | 补 Gateway 插件目录、不可变版本包、精确版本决策、包核验、统一版本和回滚 |
| 星途主应用保留 `/api/client-updates/check` 灰度客户端 | 当前 Gateway 没有该路由；它也不是插件更新接口，不能冒充两端已接通 |

## 2. 权限如何决定

### 控制哪些功能

功能使用稳定 ID；显示名称可以翻译，不用套餐名、模型名或菜单文字作为标识。以下为拟定契约。

| 功能 ID | 控制对象 |
| --- | --- |
| `text.chat` | 文本对话入口和新调用 |
| `image.generate` | 生图、改图入口和新调用 |
| `video.wan` | Wan / 通义万相视频 |
| `video.seedance` | Seedance 视频；v1、v3 共用业务权限，参数分别适配 |
| `assets.library` | 云端素材库入口及新增、上传等操作 |
| `plugins.manage` | 插件设置、安装、启停和配置管理 |
| `plugin:<REGISTERED_PLUGIN_ID>` | 一个已登记业务插件的显示和运行，使用 Gateway plugin_id，并以已核验映射关联 manifest.runtime_id |

插件管理页和具体插件分别授权。隐藏管理页后，明确获准的插件仍可运行；要禁用插件 X，必须同时配置 X 的运行权限。内置核心插件不列为可随意关闭的业务插件。

### 三种状态

| 状态 | 显示 | 新操作 |
| --- | --- | --- |
| `hidden` | 隐藏入口、搜索项和可选插件 | 拒绝 |
| `disabled` | 显示入口和不可用原因 | 拒绝 |
| `enabled` | 正常显示 | 仍需通过 Key、模型、额度等检查 |

### 计算顺序

Gateway 统一计算，星途只消费结果：

1. **先检查身份和全局限制**：未登录、账号禁用或会话失效不授予权限；未登记功能或全局 `available=false` 一律 hidden，个人开放不能覆盖全局关闭。
2. **取默认状态**：读取 `default_state`。新登记功能默认 hidden；存量功能按当前产品行为显式初始化，避免升级后全部消失。
3. **合并套餐授权**：任一有效订阅授予该功能，即设为 enabled；多个套餐取并集，没有授权则保留默认状态。
4. **应用用户覆盖**：未到期的个人设置可改为 hidden、disabled 或 enabled；移除或到期后恢复继承。
5. **落实本机限制**：星途企业配置只能进一步收紧，不能扩大 Gateway 授权；已有 readonly 保持只读含义。

admin/root 管理角色不自动授予全部业务功能。用户组、倍率、模型列表和 Gateway 的 `sidebar_modules` 也不是星途插件授权。

有效订阅按服务端时间判断：`status=active` 且 `start_time <= now < end_time`。当前 `GetAllActiveUserSubscriptions` 只检查 active 和 end_time，新增权限计算需补充开始时间判断。自然到期直接影响权限，不等待定时任务清理状态。

套餐下架只停止新购买，不撤销有效订阅。修改套餐授权会影响当前持有者，保存前显示影响范围；需要保留旧权益时使用新套餐。订阅发放、失效、删除、到期，以及用户覆盖到期，都重新计算；额度重置或耗尽不等于订阅失效，不单独改变功能授权。

## 3. 两个平台如何配合

### 职责和操作流程

| 位置 | 职责 |
| --- | --- |
| Gateway 管理后台 | “星途管理”集中提供功能权限、插件目录、版本发布；套餐/用户页直达授权和最终预览 |
| Gateway 权限服务 | 保存目录、套餐关联、用户覆盖及专用 Key 绑定；复用现有 user_id、plan_id 和订阅账本，统一计算最终结果 |
| 星途主进程 | 复用 `maasAuth.ts` 会话取权限/目录/更新决策，通过受控 IPC 下发；检查管理、安装和业务插件执行 |
| 星途界面 | 使用同一份快照控制侧栏、设置、商店/搜索、快捷键和页面直达；失权时退出操作表单 |
| Gateway 云服务 | 根据认证用户和可信应用绑定，在模型/素材新操作预扣费和上游请求前再次检查 |

操作顺序是：管理员保存规则 → Gateway 更新版本并使相关缓存失效 → 星途读取该账号最终权限 → 更新界面 → 执行新操作时再次校验。管理预览与本人读取共用计算规则，能说明某项功能来自默认、套餐还是个人覆盖。

存储使用 GORM 和事务，兼容项目支持的三种数据库；关联设置唯一约束。规则不塞入公开 option、角色或组倍率。管理写入复用已有审计链路；多节点需同步失效，缓存不得跨越最近的订阅或覆盖到期点。

### 联网与刷新

首版采用普通请求回查，不要求持续连接或桌面公网回调。主进程统一调度并合并并发刷新，界面组件订阅同一份快照，不为每个插件重复查询订阅和钱包。

| 时机 | 行为 |
| --- | --- |
| 登录、启动恢复、换号、订阅操作完成 | 重新取得当前账号权限 |
| 回到前台、系统唤醒、网络恢复 | 立即刷新；唤醒后不沿用已过期权限 |
| 前台正常联网 | 约每 30 秒回查，适度错开请求；失败重试退避 |
| 断网或读取失败 | 未过期的同账号快照可暂用；有效期最长 60 秒，不跨已知到期点，失败重试不能延长授权 |

有效期按服务端时间和单调经过时长判断，避免修改本机时钟延长权限。快照按 Gateway origin、user_id 和登录代次隔离；退出/换号立即清理，旧请求不得覆盖新账号。401 按会话流程处理；5xx/断网不伪装成退出，也不默认全开。

首次未取得权限时不闪现受限入口。快照过期后拒绝新的受控操作，保留本地成果查看和重试入口。正常联网时，后台变更在下一次成功回查后更新；30/60 秒为拟定参数，尚未实现。

### 显示和执行一起控制

插件的安装、启停、配置 IPC，以及加载、对话工具、计划任务和后台执行入口都要检查权限。现有 allow/entries 配置可作为适配边界，不能因关闭业务插件而移除内置核心插件、改写原有技能/MCP 协议或重构无关运行链路。

云能力由服务端按真实接口和规范化模型映射到功能，覆盖改图、视频 remix、Wan v1、Seedance v1/v3 和协议别名。文本带参考图片不等于图片生成；支持协议内生图工具时，也需在生成动作处检查。拒绝新调用不能产生预扣费或上游任务。

`plugins.manage` 不等于模型权限，通用模型请求也无法证明由哪个本地插件发起。插件专有云服务在实际服务边界鉴权；纯本地插件由星途执行端控制，不能承诺客户端被自行修改后仍有服务端同等强制能力。

撤销“新生成”权限后，本人任务查询、取消已受理任务、既有成果下载和账务回查仍按归属及原有权限处理。已接受任务继续结算和回收，不自动取消或退款；不删除历史、Key、项目或普通文件库数据。

### 星途专用 Key

`POST /api/apps/starpath/model-key` 不传任意目标用户或可自选的 application_id。服务端按“当前用户 + starpath”原子取得/初始化绑定，返回 `data.token_id` 与 `data.application_id`；并发请求只能建立一个当前有效绑定。Key 明文仍由已有的本人取 Key 接口按其原有规则返回。已绑定 Key 被停用、过期或耗尽时返回对应状态，不自动重建来绕过限制。

这项应用绑定及初始化契约当前不存在；普通 `POST /api/token/` 目前也不返回新 ID。未来实现需要服务端不可由普通 Key 编辑接口移除的绑定，以及明确的删除后重建、主动轮换规则；不能把名字叫“星途”的现有 Key 直接当成可信绑定。

应用归属必须由服务端绑定，不能相信 Key 名称、`X-App-ID`、客户端版本、User-Agent 或自报 plugin_id。专用 Key 离开星途调用也继续受应用权限限制；普通 Gateway Key 保持原有策略。账号级模型禁用仍使用 Gateway 自身规则，旧 Key 迁移见第六节。

## 4. 接口如何约定

### 应用身份不等于插件执行证明

服务端数据库中的应用 Key 绑定证明 starpath 应用范围；真实云动作还应由服务端按路由、协议和校验后的业务参数确定。共用通用文本接口的多个插件不能仅凭 Key、plugin_id 或自报请求头区分。需要插件级云强制许可时，先建立可验证的业务服务边界；否则只能声明受支持客户端的本机守卫和应用级能力控制。纯本地插件同样不能承诺防止修改客户端后的执行。

图片/视频的别名路径、模型映射、素材操作和恢复查询分别列入映射与验收，拒绝必须在预扣费和上游副作用前完成。不能为了授权重写官方对话、工具、办公技能或 MCP 核心执行。

**本节所有 `/api/apps/starpath/...` 地址均为设计方案，当前路由未提供，不可用于现网对接。** 已有登录、订阅和模型接口保持原契约；不为本次文档调整任何业务路由。

### 接口清单

| 方法与地址 | 身份 | 用途 |
| --- | --- | --- |
| `GET /api/apps/starpath/entitlements` | UserAuth，当前账号 | 读取本人最终功能权限，不接受代查 `user_id` |
| `POST /api/apps/starpath/model-key` | UserAuth，当前账号 | 幂等取得或初始化服务端绑定星途的用户模型 Key，返回 token_id，不返回管理员凭证 |
| `POST /api/apps/starpath/config-reports` | UserAuth，当前账号 | 回报本机处理的权限/目录版本及有限失败码，不作为授权证据 |
| `GET /api/apps/starpath/admin/users/:user_id/config-reports` | AdminAuth | 分客户端查看最近回报、服务端接收时间和是否落后 |
| `GET /api/apps/starpath/admin/features` | AdminAuth | 读取完整目录、全局状态、默认状态及 revision |
| `PUT /api/apps/starpath/admin/features/:feature_id` | RootAuth | 登记受支持功能，修改全局状态、默认状态；不能上传代码或配置任意执行地址 |
| `GET /api/apps/starpath/admin/plans/:plan_id/features` | AdminAuth | 读取指定套餐的授权列表与 revision |
| `PUT /api/apps/starpath/admin/plans/:plan_id/features` | AdminAuth | 原子替换套餐授权列表；空列表清空该套餐授权 |
| `GET /api/apps/starpath/admin/users/:user_id/feature-overrides` | AdminAuth | 读取该用户的单独覆盖与 revision |
| `PUT /api/apps/starpath/admin/users/:user_id/feature-overrides` | AdminAuth | 原子替换用户覆盖；空列表恢复继承 |
| `GET /api/apps/starpath/admin/users/:user_id/entitlements` | AdminAuth | 预览该用户全部状态、套餐/覆盖来源及下一次到期时间 |

管理端沿用 Gateway 角色边界，普通管理员不能通过该接口修改 root 的受保护配置或绕过现有目标用户权限限制。用户自己不能授予功能或修改专用 Key 的应用归属。管理写入接入已有 AdminAuth/RootAuth 审计链路，记录操作者、目标、规则变化、原因及结果，不记录 Key、Cookie 或令牌。

### 当前用户读取

```http
GET /api/apps/starpath/entitlements
Authorization: Bearer <USER_ACCESS_TOKEN>
```

拟定响应：

```json
{
  "success": true,
  "message": "",
  "data": {
    "schema_version": 1,
    "application_id": "starpath",
    "user_id": 123,
    "effective_version": "<OPAQUE_EFFECTIVE_VERSION>",
    "server_time": 1800000000,
    "valid_until": 1800000060,
    "refresh_after_seconds": 30,
    "features": [
      {"id": "text.chat", "state": "enabled"},
      {"id": "image.generate", "state": "enabled"},
      {"id": "video.seedance", "state": "disabled", "reason_code": "PLAN_REQUIRED"}
    ]
  }
}
```

用户响应仅列出可见功能；`hidden` 项不返回名称、描述或插件商店元数据。已知功能未出现在列表中即隐藏并拒绝使用，不默认开放；客户端不识别的新 ID 也不显示。时间示例为占位数值，单位均为 Unix 秒。`effective_version` 为不透明字符串，只用于判断变化，不能作为授权凭证。

`disabled` 的原因码用于提示，例如 `PLAN_REQUIRED`、`ADMIN_DISABLED`；账号失效走身份错误。订阅、目录或覆盖读取失败应返回 503 + `ENTITLEMENTS_UNAVAILABLE`，不能像空订阅列表一样按正常结果处理，更不能退回全部开放。响应使用 `Cache-Control: private, no-store` 与 `Vary: Authorization`。

### 管理配置示例

以下请求均使用管理端会话，示例 ID 需要替换。每个资源 GET 返回 revision；首次没有配置时 revision 为 0。PUT 要带 `expected_revision`，事务内比较后写入并递增，版本冲突返回 409 + `POLICY_REVISION_CONFLICT`，不覆盖其他管理员刚保存的规则。

root 修改图片功能默认状态：

```http
PUT /api/apps/starpath/admin/features/image.generate
Authorization: Bearer <ROOT_ACCESS_TOKEN>
Content-Type: application/json

{
  "expected_revision": 3,
  "available": true,
  "default_state": "disabled",
  "reason": "未获授权时显示套餐入口"
}
```

给套餐 7 授予图片和 Wan 视频：

```http
PUT /api/apps/starpath/admin/plans/7/features
Authorization: Bearer <ADMIN_ACCESS_TOKEN>
Content-Type: application/json

{
  "expected_revision": 2,
  "feature_ids": ["image.generate", "video.wan"],
  "reason": "配置套餐功能"
}
```

对用户 123 隐藏图片和插件管理页，并单独开放一个已登记业务插件：

```http
PUT /api/apps/starpath/admin/users/123/feature-overrides
Authorization: Bearer <ADMIN_ACCESS_TOKEN>
Content-Type: application/json

{
  "expected_revision": 5,
  "overrides": [
    {"feature_id": "image.generate", "state": "hidden", "expires_at": 0},
    {"feature_id": "plugins.manage", "state": "hidden", "expires_at": 0},
    {"feature_id": "plugin:<REGISTERED_PLUGIN_ID>", "state": "enabled", "expires_at": 1800086400}
  ],
  "reason": "调整该用户可见功能"
}
```

上述覆盖列表是完整替换，页面应先读取再编辑；取消某一覆盖时从列表移除该项。整个 PUT 在同一事务内校验目标、功能、时间与版本，任一项失败则不保存部分结果。写入返回该资源的新 revision；管理预览单独回查。不存在的资源返回 404，无效状态或字段返回 400，身份和角色不符分别返回 401/403。这些业务接口不沿用管理员手册的“隐藏文档存在”404 策略。

配置回报的字段、30 天保存期、幂等作用域和错误码以第三章“配置生效回报与管理端观察”为准。回报与安装 report 分开；管理员看到客户端自报应用，不等于服务端验证真实执行，不能据此放宽权限或延长快照。

## 5. 按什么顺序开发

开发前先整理“功能 ID → 页面 → 主进程操作 → 模型/服务接口 → 插件运行时 ID”的对应表，确认实际业务插件及所有执行入口。无法拦截的路径先解决，再开放相应功能。

以下六阶段均待开发。先用插件管理和一个业务插件验证完整链路，再接图片、Wan、Seedance、文本和素材库；全部模块及发布控制都要进入最终验收。

| 阶段 | 责任端与依赖 | 交付和完成条件 |
| --- | --- | --- |
| P1 权限服务 | Gateway；依赖功能对应表 | 完成第四节接口、存储、计算、版本/审计、专用 Key 绑定及缓存失效；本人读取与管理预览一致，事务、到期和数据库兼容测试通过 |
| P2 管理后台 | Gateway；依赖 P1 | 接入目录、套餐、用户配置与结果预览，完成导航及七种语言；角色边界、继承结果、保存冲突可验证 |
| P3 显示与同步 | 星途；依赖 P1 | 接主进程快照、受控 IPC 和界面守卫；刷新、有效期、断网、唤醒、换号及迟到响应符合第三节 |
| P4 执行限制 | 两端；依赖 P1、P3 | 接业务插件各执行入口、专用 Key 和云服务鉴权；绕过尝试被拒绝且不预扣费，核心能力和成果回收正常 |
| P5 插件发布控制 | 两端；依赖 P1–P4 | Gateway 版本草稿/发布/撤销和唯一统一策略；星途精确包校验、二次授权、安装健康检查、强制更新及回滚 |
| P6 联调上线 | 两端；依赖 P1–P5 | 完成第六节与发布验收、旧版/旧 Key 迁移、统一发布及恢复验证 |

P2、P3 可在 P1 契约稳定后分别开发。界面演示不替代 P4；可信 Key 绑定和多节点失效不得省略。

计划涉及的改动位置：

| 仓库 | 范围 |
| --- | --- |
| Gateway 后端 | `model/`、`service/`、`controller/`、`middleware/`、API 路由及现有模型/素材调用边界 |
| Gateway 前端 | `web/src/features/`、现有 subscriptions/users 页面、侧栏及 i18n；沿用主题和组件 |

## 6. 如何验收和上线

### 先验证完整链路

准备普通账号 A、B，初始都能管理插件并使用业务插件 X。管理员仅将 A 的 `plugins.manage` 和 X 设为 hidden，B 保持继承：A 应看不到入口且无法新执行 X，B 正常；正常测试网络下记录更新延迟，目标不超过 60 秒。之后验证同设备换号、重启、旧响应回写、撤销覆盖、套餐授予/到期和断网，始终保留已有成果。

这个样例通过后，将下列场景覆盖到全部首期模块及实际协议。

| 验收范围 | 通过条件 |
| --- | --- |
| 身份和管理权限 | 匿名/失效会话、普通用户访问管理接口被拒绝；root 管全局，管理员按目标权限管套餐和用户；写入可审计 |
| 规则与生命周期 | 三状态、默认、套餐并集、个人覆盖/撤销/到期、全局关闭符合第二节；未来订阅与到期未清理状态均不误授予 |
| 套餐与额度 | 下架不撤销有效订阅，重复订阅不重复叠加功能；额度重置/耗尽不误作失权 |
| 账号和缓存 | 换号/迟到响应不串权，唤醒/断网不延长授权；服务端多节点及订阅变更后结果一致 |
| 插件管理和运行 | 隐藏页不能直达；IPC、工具、计划任务不能绕过；隐藏管理页但单独授权的插件仍可运行，核心插件正常 |
| Key 和云调用 | 并发初始化不重复绑定；改名称、伪造头、换协议/参数不能绕过应用限制；拒绝请求不预扣费 |
| 一致性和错误 | 管理版本冲突/非法项不部分保存；数据库/缓存读取失败不按授权成功处理 |
| 任务和数据 | 撤销后不能新发受限任务，既有任务取消/回收、本地文件和历史查看正常 |
| 实现质量 | 后端确定性测试及三数据库/多节点验证；前端角色、i18n、类型/lint/构建检查；星途相关测试、主进程编译和真实桌面操作 |
| 联调记录 | 记录实际生效延迟、支持的客户端/Key 范围；真实支付、模型生成和平台验收是否完成分别说明 |
| 发布控制 | 元数据变更不安装包；全体获授权用户同一目标；截止前后精确版本要求正确；暂停、撤销、下载后变更、包校验失败及不兼容回滚均有确定结果 |

### 再逐步上线

1. **服务端先准备**：在隔离环境验证迁移、存量默认清单和接口兼容，再按正式流程发布服务能力；不自动改真实用户、订阅和 Key。
2. **发布支持权限的星途版本**：在隔离测试环境绑定专用 Key，验证界面、执行、断网和恢复，通过后统一发布。
3. **统一上线后观察**：监测权限读取失败、同步延迟、拒绝原因、Key 迁移和调用结果，完整首期验收通过后统一覆盖全部受支持用户，不按人群分版本。
4. **记录旧版边界**：未升级客户端不能自动获得本地显示控制，不列入“已全面受控”。版本信息只用于升级提示和诊断，不作为授权身份。

旧普通 Key 仍遵循原有 Gateway 策略。要求旧版本云调用也必须受限时，单独评估 Key 迁移或账号级模型访问调整；本地功能仍需客户端升级。支持权限契约后，调整已有功能通常无需发安装包；新增客户端没有的功能或改变执行机制仍需升级。后续可增加推送加速更新，不替代服务端校验。

### 故障怎么恢复

误配通过正常版本检查重新保存上一份已核对规则，产生新 revision 和审计，不直接倒退版本或改库。root 可全局关闭故障功能；读取故障遵守快照有效期，不能默认全开。

客户端只回退到仍支持当前契约的版本；服务端保持向后兼容，不删除授权记录或解除应用绑定。数据库迁移及正式上线操作在后续发布任务执行，本轮没有执行。

### 当前交付状态

本轮按参考 PDF 的逐接口粒度补齐六章手册，并同步合并审阅版；第三章已经包含可直接审阅的字段表、请求/响应、错误、刷新、发布和回滚契约。P1–P6 均未实现，功能测试、两端联调及真实用户验收尚未完成，未改运行环境、未提交或推送。文档检查不代替功能验收。

## 7. 发布控制和套餐详情的实施约束

详细契约见手册第二、三章，以下为实现时必须同时满足的边界：

| 范围 | Gateway | 星途 |
| --- | --- | --- |
| 套餐商品 | 复用 plan_id，计费定义/展示详情/功能授权独立保存；说明跨请求非原子 | 只读可购聚合详情，支付后重读真实订阅和最终功能 |
| 插件目录 | 固定 plugin_id/runtime_id/feature_id；draft/listed/unlisted；目录下架不等于全局停用 | 合并本机安装状态，hidden 不展示，不依赖显示名映射运行时 |
| 不可变版本 | 草稿核验固定 URL、大小、SHA256、manifest、支持平台，发布后不可改包 | 不跟随 npm/clawhub 的 latest，按获准 release 精确安装 |
| 安装兼容 | 保存 runtime_id/package_name、npm_tgz 格式、固定宿主/Node、schema 版本、已登记兼容规则和工具能力 | 包身份/依赖/SDK 验证，复用 CLI staging；不以下载摘要代替全部安装验证 |
| 统一版本 | 每插件唯一目标与期限，平台/架构匹配同版本包，不按用户或套餐分流 | 不提供自主选版，账号只参与使用/下载授权 |
| 强制更新 | 下发精确 target_version/deadline_at；暂停仍保留统一版本要求 | 截止后只运行指定版本，升级/停用/历史通道保留 |
| 下载与安装 | 短时决策，download/install 各次重新授权；撤销及时失效 | CDN 不带 Gateway Bearer，校验后 staging/原子切换/健康检查 |
| 回滚 | 将当前统一策略改为 rollback，from_versions、指定安全旧包及兼容条件 | 显式提示降级，数据可逆才回退；失败保留准确状态 |
| 观察 | 用户归属和幂等保护的操作结果；不把自报成功当授权证据 | 不上传敏感路径/凭证，不能伪报所有升级成功 |

现有 user_plugins 没有 Gateway origin/user_id 维度，需新增账号关联且保留用户的 desired_enabled；不把暂时失权永久写成本机关闭。现有 publisher 切换成功即删备份，不能直接承诺健康失败回滚，需保留旧代及对应本地元数据到验收成功。

新增存储和关联使用 GORM、事务及唯一约束，支持 SQLite/MySQL/PostgreSQL。现有套餐写入没有 expected_revision，新授权/发布资源才使用文档拟定乐观锁；不能把新契约倒写为现有接口能力。设计需先完成真实运行时 ID 和安装器适配，未支持平台不得发布或承诺回滚。
