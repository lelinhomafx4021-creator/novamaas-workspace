后台修改名称、排序、可见性、套餐或参数属于配置变更；只有需要新代码或修复代码时才发包。插件版本策略不承担套餐授权，套餐变更也不触发自动安装。关闭手册阅读开关仅停止阅读，不停止客户端业务或撤销插件权益。

远程强制控制范围必须逐条说明：

- 受支持的星途客户端在页面、IPC、业务工具和计划任务入口落实本机权限与版本检查。纯本地执行依赖客户端配合，不能承诺修改客户端后仍无法绕过。
- 云接口按真实认证用户、数据库中的应用 Key 绑定、服务端确定的业务动作检查。不能信任客户端的插件名称、`X-App-ID`、`feature_id` 或自报版本来授予权限。
- 多个插件共用 `/v1/chat/completions` 时，应用 Key 能证明应用归属，不能证明调用来自哪个插件。通用文本路由只能执行其能可靠判定的文本权限；需要插件级云授权时，必须先建立可验证的独立业务服务边界。未建立边界的能力不得验收为“服务端强制插件授权”。
- `plugins.manage` 控制管理入口及管理操作，独立业务功能控制新执行。隐藏管理页不应关闭仍获授权的业务工具、核心确认工具、原办公技能或 MCP。

## 4. 每条链路的输入、输出与失败处理

### 4.1 登录到第一次调用

1. 主进程读取 status，按启用方式登录；完成二次验证后保存当前 origin/user.id/session.sid 与登录代次。
2. 读取 self/status 和 subscriptions；账号解析失败不沿用另一账号的钱包或套餐。
3. 核实选定模型 Key 的所有者、状态、到期、分组与预算；用它读 `/v1/models`。账号登录成功不等于模型已经可调用。
4. 专用 Key 和权限服务完成后，读取本人 entitlements、可见 plugins 和统一更新要求；现在不能调用不存在的拟新增接口，也不能伪造 enabled 快照继续测试。
5. 执行前主进程检查本机允许条件；云服务完成其可信鉴权后才预扣费/转发。第一笔调用由用户主动触发，记录请求与实际结果。
6. 保存结果，再刷新实际用量与订阅；无法确认的调用标记待确认，不自动再次付费提交。

### 4.2 管理变更到客户端生效

读取目标资源和 revision → 提交完整请求及 reason/expected_revision → 服务端事务保存并审计 → 变更相关有效版本/失效缓存 → 后台重读与预览 → 客户端刷新本人快照 → UI 和新执行同时生效 → config-reports 回报本机应用结果。

拟新增 `POST /api/apps/starpath/config-reports` 和管理端目标用户 GET：按真实用户、随机 client_instance_id、report_id 隔离，服务端记接收时间，保留最近 30 天；字段/冲突规则见第三章。管理端观察最近版本、失败和未回报状态，不能把自报 applied 当执行证明或授权依据。该链路与包安装 report 分开。

后台同时保存套餐计费、商品说明与功能授予时，现有/拟定接口是多个请求；需逐项展示保存结果。不能一项成功就提示三项全部保存，也不能在权限保存失败时撤销已完成的真实支付。冲突返回后重读，由操作者重新提交，客户端不得覆盖最新规则。

功能前台回查建议 30 秒，权限快照最长 60 秒，不能跨越已知订阅或覆盖到期点。正常网络下管理变更至客户端的目标延迟不超过 60 秒；该目标须真实测量。服务端的新执行鉴权不能等客户端刷新才能拒绝。多节点验证包括数据库已更新但另一节点仍持旧缓存的情况。

### 4.3 统一更新与回滚

作者提交固定包及完整元数据 → Gateway 核验并登记草稿 → 发布锁定产物 → 保存同一目标版本及所有支持平台文件 → 用户权限通过后 check → download 授权 → 下载/解包校验 → install 再授权 → 同卷切换 → 配置与真实注册/健康检查 → report。

后台暂停停止新安装授权，保留已有版本要求；撤销包立即使新的安装授权失效；两者均不等于自动回滚。回滚须设置明确安全旧目标、允许的 from_versions、全部平台文件及数据可逆条件，仍走校验和健康检查。失败时恢复文件与对应元数据；无法安全恢复时如实上报并停用该插件，保留历史。

所有获授权用户对同一插件执行相同目标及期限。不通过套餐、人群、比例、通道或客户端自主选版形成不同目标。客户端整体升级与业务插件发包分开；当前 Gateway 没有 `/api/client-updates/check`，不能复用插件接口冒充主应用升级服务。

### 4.4 结果和标识不能混用

| 标识 | 谁生成 | 用途与保存位置 |
| --- | --- | --- |
| user.id / token_id | Gateway | 账号及 Key 关联；不保存成业务插件 ID |
| X-Oneapi-Request-Id | Gateway | 排查请求；网页跨域能否读取需单独确认，不能拿它保证请求幂等 |
| 模型 response id | 模型/适配器 | 协议结果关联；不保证 Gateway 保存上游对话状态 |
| 公开 task_id | Gateway | 视频查取/取消/下载；同时保存提交协议和模型，不拼上游 ID |
| plugin_id / runtime_id | Gateway 目录/manifest | 商品身份与本地运行身份；映射需核验 |
| release_id / package_sha256 | 发布管理 | 精确产物身份；版本字符串一致仍要核验文件 |
| decision_id / operation_id | 授权服务/客户端安装流程 | 短期授权与安装进度分别保存，不能互相冒充 |
| effective_version / 各资源 revision | 权限/配置服务 | 变化检测与乐观锁，不能跨资源比较或当作授权凭证 |

## 5. 待开发数据契约与兼容迁移

采用[第三章](../admin-manual/03-api-keys.md)的公开字段与错误码。下列为后端/客户端实施要求，不是本次新增的数据库模型。

| 资源 | 唯一性/版本约束 | 更新与失效 |
| --- | --- | --- |
| 功能定义 | application_id + feature_id；资源 revision | 全局关闭优先于任何授予；未知功能默认拒绝 |
| 套餐功能集 | application_id + plan_id；集合 revision | 原子替换并集来源，变更影响全部当前有效持有人 |
| 用户覆盖集 | application_id + user_id；集合 revision，覆盖可到期 | 空集恢复继承；不能绕过全局关闭 |
| 套餐展示 | application_id + plan_id；独立 revision | 展示说明与账务字段分开，Markdown 净化 |
| 应用 Key 绑定 | application_id + user_id 唯一当前绑定 | 并发初始化不重复；已删除需显式重新绑定，停用/过期不自动换 Key |
| 插件目录 | application_id + plugin_id；runtime_id 固定核验 | draft/listed/unlisted，不将核心/provider/随包渠道误作商品 |
| 不可变发布物 | release_id；plugin/version/platform/arch 对应固定内容 | published 后不能覆盖文件；撤销记录保留 |
| 统一策略 | 每个 plugin_id 唯一当前策略；revision | 全平台原子校验，权限/策略变化使旧安装决策失效 |
| 幂等记录 | 按第三章指定的账号、方法、资源、key 作用域 | body 冲突拒绝；授权重放仍重查有效性，不延长链接寿命 |
| 本机账号插件状态 | gateway_origin + gateway_user_id + plugin_id | desired_enabled/config 按账号隔离；共享包不共享权限或凭据 |
| 配置应用回报 | user_id + client_instance_id + report_id；保留 30 天 | 只记录版本和有限失败码；管理员按各客户端最新一条观察，不参与授权 |

迁移按新增兼容数据、验证映射、启用新读取、再开放写入推进，使用 GORM 和三数据库兼容写法。先在隔离测试库验证事务/唯一约束/并发；本地真实联调使用既有 `newapi-mysql` 的 `novamaas_local`、后端 3000，配置来自忽略的环境文件，不从备份库取渠道。

旧 Key 不按名称批量认领，不静默创建替代 Key；旧 user_plugins 配置不自动归给当前登录用户。先盘点原配置，区分可共享包和账号私有配置，以可回退迁移记录保存关联。无法确认的归属保留原数据并提示重新绑定。切换客户端账号不触发插件目录或包的删除。

数据库回退优先关闭新增能力的入口并保留新增记录，不自动删除生产列、授权、账本或用户配置。服务端和客户端回退分别验证；回退到不了解受控插件规则的旧客户端不能宣称继续满足统一管控。

| A1 两端验收与上线 | 两端负责人及运营验收 | I1、G2、C1、R2 | 下节全部范围有结果；分系统安装/升级/回滚记录；未完成项和发布范围一致 |

G2 与 C1 在 G1 契约稳定后可以独立推进，但不能用页面演示跳过执行校验。新建 Gateway 能力由 Gateway 任务独立实施；星途任务只消费已经交付的接口，不越过其工作区只读边界修改另一个仓库。

R1/R2 是最终范围，不能因先交付权限就删去统一发布要求。购买/支付界面、主应用升级服务、完整云端会话历史、通用文件库、报价服务另列决策；现有接口清单不等于批准恢复全部产品入口。

## 7. 联调场景与通过条件

每条场景使用明确账号和目标，不使用生产凭证作为样例。真实付费、外部消息、安装/发布及回滚分别在已授权环境执行；本手册收口不执行这些业务操作。

| 编号 | 前置与操作 | 预期结果 / 证据 |
| --- | --- | --- |
| AUTH-01 | A 登录、刷新、撤销会话；同机换 B，放回 A 的迟到响应 | B 的账号/Key/钱包/权限不被覆盖；失效凭证不静默转成其他身份 |
| BILL-01 | 读取不同额度显示单位；主动调用一次后刷新；再模拟刷新失败 | 数值来自真实账本；旧数据标记陈旧，失败不改成零；不客户端结算 |
| PLAN-01 | 两份有效套餐授予同一功能；失效其中一份；下架另一套餐 | 并集仍授予有效来源；下架不撤销既有订阅；到期规则正确 |
| PERM-01 | A 个人 hidden，B 继承；尝试直达、快捷键、IPC、工具及计划任务 | A 无新执行和外部副作用，B 正常；历史仍可查看 |
| PERM-02 | 全局关闭、清覆盖、覆盖到期；另一节点持有旧缓存 | 全局关闭优先，多节点不误授予；记录真实生效延迟 |
| SYNC-01 | 两设备处理新快照，一台失败；重放/冲突回报，再同机换号 | 分设备显示 applied/partial/落后；不串账号，不因回报授予权限或延长有效期 |
| KEY-01 | 并发初始化、停用/过期、删除绑定、修改名称、伪造应用头 | 不重复创建，不绕过绑定与停用；删除后显式重新绑定 |
| CLOUD-01 | 应用 Key 调用受控图片/视频与别名协议；改变插件自报字段 | 服务端可靠动作映射一致；无法判定插件来源的通用文本请求不被误标为插件强制鉴权 |
| TEXT-01 | Chat/Responses/Claude/Gemini 各自同步/流式及工具调用，中途停止 | 按支持矩阵运行；未支持组合明确排除；无重复工具/假成功 |
| IMAGE-01 | URL/Base64、multipart 编辑、部分图/最终图、结果保存失败 | 同步正确结束；预览不当最终；保存失败不自动重生成 |
| VIDEO-01 | Wan/Seedance v1/v3 分别提交、重启后恢复查询、失败/取消/下载 | task_id/协议/账号不串；不支持的取消明确反馈；不因轮询超时重提 |
| ASSET-01 | 素材导入 Processing → Active，跨账号和缺渠道副本；Webhook 重复/乱序 | 归属与可用性双重检查；回查收敛，回调不重复触发生成/扣费 |
| REL-01 | 两个获授权账号、不同平台，检查同一插件目标 | 同一版本与期限；不同系统仅包文件不同；不支持的平台明确拒绝 |
| REL-02 | 下载后改策略或撤销包，再执行安装授权；摘要/包身份错误 | 拒绝旧决策或错包，保留原配置及可恢复旧代 |
| REL-03 | 截止前后/断网/换号/安装中退出，及安装后真实注册失败 | 到期不放行不合规版本；无假 succeeded；日志可恢复；不影响其他核心功能 |
| REL-04 | 管理端统一回退；验证可逆与不可逆迁移、恢复失败 | 可逆才回退文件与元数据；不可逆明确阻断；失败如实报告 |
| UI-01 | 权限变更后刷新页面、移动窄窗、键盘、七语言和保存冲突 | 视觉状态与有效权限一致；失败可重试，无隐藏授权泄漏 |
| NATIVE-01 | macOS/Windows/Linux 分别安装、升级、重启及回退 | 分平台记录；编译通过不能替代原生安装/执行验收 |

D0 只验收阅读和文档，不勾选 PERM/REL 等尚无业务实现的场景。I1 可先验证现有媒体接口；新增权限和统一更新场景必须在对应交付后运行。任一平台未实测时标“待验收”，不能汇总为跨平台全部通过。

## 8. 证据、缺口与交接方式

每条联调记录至少包含场景编号、两端 commit 与未提交改动说明、系统/架构、宿主/运行时版本、模拟或真实环境、前置条件、操作、预期/实际、结论、日期、脱敏证据和关联缺陷。不得包含密钥、Cookie、密码、完整 DSN 或带鉴权请求。

本地原始请求/响应和脚本置于忽略的 `.local-tests/`，仅把脱敏摘要作为评审材料。测试首次失败及修复后的复跑分别保留；源码核对、自动测试、本地服务、GitHub CI 和真实平台验收分列。

| 待落实项 | 采用的当前边界 | 进入实施时需要的输入 |
| --- | --- | --- |
| 首个业务插件 | `example.storyboard` 仅契约样例 | 真正作者、包、runtime_id、业务动作、配置 schema 和计费来源 |
| 发布平台 | 不预设任何平台已支持 | 每个平台/架构产物、宿主和 Node 兼容、健康检查命令及恢复方式 |
| 模型参数与报价 | `/v1/models` 为实际 Key 目录，pricing 仅部分元数据 | 按模型/协议维护能力表；报价如建设需明确身份、有效期与最终账本关系 |
| 统一订单回查与购买 | Gateway 原有接口；星途阶段只读 | 客户端购买范围、幂等、订单到订阅关联、未知结果与退款业务规则 |
| 旧 Key/配置归属 | 保留原数据，不按名称猜测 | 可核实用户关联、显式绑定步骤和迁移回退记录 |
| 插件级云强制控制 | 按可验证服务边界承诺 | 对共用协议无法判定的插件，先确定独立业务服务方案 |
| 主应用更新 | 不冒充已有服务 | 独立客户端更新协议、签名产物、版本兼容和原生升级验证 |
| PDF 原件 | 保留原差异矩阵及来源说明 | 原件恢复后单独记录版本/摘要和新逐页检查，不追写为本次已复核 |

交付时先审 D0：审阅稿能由六章重新生成、源码引用可定位、现有接口可核对、规划状态不会误当实现。后续 PR 引用本计划的阶段和场景编号，并同步更新相关正文及状态；接口字段或行为改变必须同时更新示例和失败处理。

文档维护命令在 `web/` 执行：`bun run docs:admin-manual` 更新审阅稿，`bun run check:admin-manual` 校验正文/规划/审阅稿，完成生产构建后再执行 `bun run check:admin-manual-isolation`。不得将设计正文导入前端包或公开 OpenAPI 来解决阅读入口问题。
